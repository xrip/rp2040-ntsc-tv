# HDMI text: оптимизация RP2350 / Cortex-M33

Дата: 2026-10-26. Репозиторий: `xrip/rp2040-ntsc-tv`, ветка
`vga-tv-hybrid`. Базовый коммит:

```text
231f1fa7e50368ee07fb72330377a15c0208ede5
Speed up HDMI text scanout with PIO glyph expansion
```

Добавлены отдельные Thumb-2 циклы для Cortex-M33. По исполнению итоговых
RP2350 ELF программная часть HDMI IRQ выполняет **на 28–29% меньше инструкций
за полный кадр в режимах 80 колонок и на 24,7% меньше в 40×25**, по сравнению
с уже ускоренным PIO-драйвером из базового коммита.

Workspace остаётся **4 896 байт**. В текущем текстовом/3D демо занятая
`.data` выросла всего на **40 байт**, которые поместились в существующий
промежуток выравнивания. Итоговое резервирование RAM осталось прежним.
Стек программной части IRQ уменьшился.

Это подтверждённые счётчики исполненных инструкций и размеры собранных
программ. **Процент снижения инструкций не является измерением снижения
времени CPU. Новая версия не профилировалась на физической плате.**

## Local integration check, 2026-10-27

Arm GCC 15.2.1 builds the RP2350 and RP2040 text/3D demos. Host tests, PIO
checks and both IRQ audits pass. The linked M33 case suite and all 976 kernel
length/alignment cases pass under WSL, including output and register checks.
The shared M0+ trace also passes after the test-tool changes. The tables below
describe the supplied archive's toolchain and measurements.

## 1. Что изменено именно для M33

Перенос разворачивания пикселей в PIO уже работал на обоих чипах. Предыдущая
специализация CPU содержала ассемблерные циклы M0+; на M33 оставался общий
C-вариант. Теперь M33 использует собственные возможности Thumb-2.

### 80 колонок

Основной цикл обрабатывает четыре символа за проход, двумя парами.
Внутри пары чередуются независимые чтения атрибутов и шрифта, чтобы уменьшить
последовательности зависимых загрузок. Используются адресация со сдвигом,
объединённый ORR со сдвигом, автоматическое продвижение указателей и STRD
для записи двух готовых команд.

Для обычного шага шрифта цикл выполняет **32 инструкции на четыре символа,
то есть 8 на символ**, вместо 12 у C-версии. Это число относится к телу
цикла; полная трасса ниже учитывает подготовку, пролог, эпилог и поля кадра.

Нечётный первый символ обрабатывается отдельно. Оставшееся нечётное число
пар начинает выполнение со второй половины развёрнутого цикла. Поэтому
перенос VRAM с участками длиной 1, 2, 3 или любым другим допустимым числом
ячеек не требует чтения за границей участка или копирования строки.

### 40 колонок

Два полубайта строки глифа извлекаются фиксированной маской и сдвигом.
Порядок записываемых команд выбирается перед циклом по порядку битов шрифта.
Так устранены две переменные операции сдвига и избыточные маски на каждом
символе. Цикл занимает **14 инструкций на символ вместо 19** и записывает
обе команды одним STRD.

### Заполнение полей и гашения

M33 заполняет по четыре 32-битных слова за проход парными записями STRD.
Размеры областей известны в местах вызова, поэтому компилятор удаляет
ненужные проверки остатков. Восьмибайтовое поле в конце строки превращается
в одну STRD без цикла. Дополнительные регистровые копии цвета и буферы
для этого не понадобились.

VRAM и шрифт продолжают читаться **побайтно**, в том числе при нечётном
адресе предоставленного приложением буфера. STRD применяется только
к внутренним выходным буферам с выравниванием минимум четыре байта.
Такое выравнивание для двухсловного доступа допустимо по §3.3.5
[Cortex-M33 Generic User Guide](https://documentation-service.arm.com/static/66be2153882fec713ef49e49);
условия использования STRD описаны в §3.14.3 того же документа.

Все производственные изменения находятся в `drivers/hdmi/hdmi.c`.
Общий API, формат команд, таблицы, PIO-программа, DMA и источник шрифта/VRAM
сохранены. Для RP2040 используется прежний Thumb-1 путь. Другие цели
сборки сохраняют C-вариант. Новый код выбирается автоматически при
`PICO_RP2350 && defined(__ARM_ARCH_8M_MAIN__)`.

## 2. Полный кадр: до и после

Каждая строка таблицы включает **525 вызовов реального IRQ из связанного ELF**,
его программный пролог/эпилог, подготовку текста, поля и синхронизацию.
Обе стороны собраны одним toolchain на основе указанного коммита.

| Режим | Было, инструкций/кадр | Стало, инструкций/кадр | Снижение |
|---|---:|---:|---:|
| 80×30 | 623 058 | 446 747 | **28,30%** |
| 80×25 | 557 898 | 394 307 | **29,32%** |
| 40×25 | 479 098 | 360 707 | **24,71%** |
| 80×30: MSB, blink, курсор, wrap с коротким участком и нечётные указатели | 632 669 | 455 510 | **28,00%** |

Для обычных кадров максимальное число инструкций одного проверенного IRQ
изменилось следующим образом:

| Режим | Было | Стало |
|---|---:|---:|
| 80×30 | 1 274 | 924 |
| 80×25 | 1 267 | 917 |
| 40×25 | 1 070 | 833 |

Отдельно вызов ядра разворачивания полной активной строки, включая его
подготовку и возврат, изменился с **977 до 659 инструкций** для 80 колонок
и с **779 до 574** для 40 колонок.

### Почему здесь нет «точных процентов CPU»

Unicorn выполняет ARM-код с выбранной моделью Cortex-M33 и позволяет проверить
результат, обращения к памяти и число инструкций. Он не моделирует такты
реального RP2350, арбитраж SRAM с DMA и вторым ядром, очереди, задержки памяти,
вытеснение другими IRQ или конкуренцию за блокировки.

Кроме того, M33 поддерживает ограниченное одновременное исполнение некоторых
пар 16-битных инструкций; длина и состав последовательности имеют значение.
Это описано в [Arm Cortex-M33 Processor Datasheet](https://www.arm.com/-/media/Arm%20Developer%20Community/PDF/Processor%20Datasheets/Arm-Cortex-M33-Processor-Datasheet.pdf).
Поэтому снижение инструкций на 28% не следует автоматически объявлять
снижением времени IRQ на те же 28%.

Предыдущие расчёты тактов Cortex-M0+ также не переносятся на M33.
Для фактической доли ядра и худшей задержки строки нужен замер GPIO
с реальным эмулятором. Число IRQ, частоты и видеотайминги не менялись.

## 3. Память

### Текущее текстовое/3D демо RP2350

| Показатель | Базовый коммит | С оптимизацией |
|---|---:|---:|
| Workspace HDMI | 4 896 Б | **4 896 Б** |
| Занятая `.data`, включая исполняемый из SRAM код | 6 172 Б | **6 212 Б** |
| `.bss` | 200 480 Б | **200 480 Б** |
| Промежуток выравнивания | 1 748 Б | **1 708 Б** |
| Область RAM до конца резервации heap | 210 720 Б | **210 720 Б** |
| Отдельная резервация стека | 2 048 Б | **2 048 Б** |

Таким образом, реально занятых байт стало на **40 больше**, а существующего
промежутка выравнивания — на 40 меньше. Копии шрифта, видеопамяти, дополнительного
framebuffer, новых таблиц и динамических выделений нет.

В контрольной сборке со всеми функциями и одинаковыми буферами обе стороны
занимают 97 360 байт основной RAM; занятая `.data` также растёт на 40 байт.
В исходном приложении только с графикой результат LTO другой: занятая
`.data` растёт на 28 байт, но общий размер остаётся 201 788 байт.
Следовательно, **+40 байт не является универсальным числом для любого
приложения**, как и нулевой итоговый прирост. Проверять нужно карту памяти
конкретного эмулятора. Размер workspace везде остаётся неизменным.

У RP2040 в проверенных сборках размер памяти сохранён. Все пять горячих
HDMI-функций и вся `.data` его текстового демо совпадают с базовой версией
побайтно; специализация M33 в эту сборку не попадает.

### Стек программной части IRQ

| Режим | Было | Стало | Изменение |
|---|---:|---:|---:|
| 80 колонок | 176 Б | **168 Б** | −8 Б |
| 40 колонок | 184 Б | **164 Б** | −20 Б |

Это максимумы проверенных трасс программного обработчика, включая вложенные
вызовы. Аппаратный кадр исключения не включён. Резервируемые размеры стеков
не увеличивались.

XIP-кэш для этой оптимизации не резервируется. Горячий код расположен
в SRAM; при предоставленном SRAM-шрифте и VRAM проверенные IRQ не обращаются
к flash. Прямой указатель на шрифт во flash по-прежнему оставляет задержки XIP
на ответственности приложения.

## 4. Проверки

Итоговый RP2350 ELF прошёл:

- **85 сценариев IRQ**: геометрия, шрифты 8/14/16 строк, шаг шрифта 32,
  оба порядка битов, курсор, blink, повторные переходы его состояния,
  перенос VRAM и нечётные адреса входных буферов.
- **976 вызовов реальных связанных ядер**: каждая длина от 0 до 80 или 40,
  оба порядка битов, чётные/нечётные входные адреса и выходное выравнивание
  0 либо 4 по модулю 8. Проверяется ровно одно чтение байта шрифта на ячейку,
  точный результат и границы участка.
- **Четыре полных кадра**, включая сценарий с дополнительными функциями.
  Столько же кадров выполнено на базовой версии для сравнения.
- Проверки сохранения r4…r11 и SP, границ буферов, отсутствия записи
  в другую DMA-строку, VRAM или шрифт.
- Проверки графических строк и их вертикального повторения.

В восьми полных кадрах проверены 4 200 возвратов из IRQ и все выходные
пиксели. Во всех проверенных горячих путях — ноль выборок инструкций
и чтений данных из XIP.

Общие host-тесты также прошли: 52 341 проверка текстовых функций,
786 432 комбинации команд для каждой из четырёх конфигураций кодека,
495 712 команд независимого PIO-симулятора и остановки FIFO.
Эти проверки дополняют исполнение M33 ELF; сами host-тесты не выполняют
ассемблерный M33-путь.

Сборки и аудит достижимых вызовов IRQ выполнены для обычного демо,
контрольного приложения, исходной графики и GPIO-профилирования.
В архиве находятся подробные отчёты, JSON, журналы, карты памяти
и инструменты воспроизведения.

## 5. Применение и измерение

Патч `hdmi-rp2350-fast.patch` применяется к коммиту `231f1fa`:

```sh
git apply --check /path/to/hdmi-rp2350-fast.patch
git apply /path/to/hdmi-rp2350-fast.patch
```

Предыдущая PIO-оптимизация уже находится в этом коммите.
Файл `APPLY.md` архива описывает состав, сборку и интеграцию.
Готовые обычные UF2 находятся в `firmware/rp2350/` и `firmware/rp2040/`.

Для самостоятельной сборки RP2350:

```sh
export PICO_SDK_PATH=/path/to/pico-sdk
export PICO_TOOLCHAIN_PATH=/path/to/arm-gnu-toolchain
cmake --preset rp2350-hdmi-text
cmake --build cmake-build-rp2350-hdmi-text --target ntsc-tv
```

Для профилирования на свободном GPIO22:

```sh
cmake --preset rp2350-hdmi-text -DHDMI_PROFILE_GPIO=22
cmake --build cmake-build-rp2350-hdmi-text --target ntsc-tv
```

GPIO25 у демо занят индикатором. GPIO22 также должен быть свободен
в конкретном устройстве. По умолчанию профилирование отключено.

Измерьте долю высокого уровня за полный кадр и самый длинный импульс.
Маркер охватывает тело IRQ с реальными ожиданиями шин/блокировок;
пролог/эпилог функции и аппаратный вход/выход из исключения находятся
за его пределами. Для оценки эмулятора измерять нужно его сборку
с обычной нагрузкой обоих ядер.

При аппаратной проверке пройдите 80×30, 80×25 и 40×25, все цвета,
одноточечную шахматку, blink/курсор, изменение шрифта и переход текст→3D→текст.
Сохранены GPIO12…19, исправления flash RP2350 и прежний цикл демо.
